Abstract

Autonomous agents driven by Large Language Models (LLMs) increasingly invoke external tools, process untrusted third-party data, and execute state-changing actions. However, modern autoregressive Transformers process trusted system instructions and untrusted external data within a unified sequential context, exposing agents to Indirect Prompt Injections (IPI). Prior defenses suffer from severe operational dilemmas: discriminative classifiers (e.g., Meta PromptGuard-86M, PIGuard) trigger catastrophic utility collapse by over-blocking non-malicious tool invocations or halting execution entirely, while generative rewriters and attention sanitizers impose severe latency overhead and context degradation.

To resolve this impasse without requiring multi-billion-parameter retraining, we present TriGuard, a lightweight, three-tier authorization and execution-gating framework for tool-augmented agents. TriGuard decouples authorization from unconstrained model generation through: (1) a Capability Microkernel (Tier 1) issuing cryptographically signed (HMAC-SHA256), timestamped, nonce-bound capability tokens enforcing strict least-privilege and default-deny tool access; (2) Provenance-Aware Context Mediation (Tier 2) cordoning off untrusted retrieved data into passive data planes with role separation; and (3) an Intent-Consistency Verifier (Tier 3) that gates structured tool calls before any external side effects occur, coupled with an out-of-band Clarification State Machine (PENDING → CONFIRMED | DENIED) for ambiguous operations.

We evaluate TriGuard on physical dual-GPU hardware using Meta-Llama-3.1-8B-Instruct across the 7 standardized core QA and RAG benchmarks of PIArena (N=1,100 samples) under Direct and Combined multi-vector injection attacks, compared head-to-head against 5 baseline conditions: Undefended Baseline, PIGuard, PromptGuard-86M, DataFilter-8B, and PISanitizer. Furthermore, we formally verify TriGuard against a comprehensive test suite of 26 adversarial security edge cases (signature forgery, scope tampering, token expiration, nonce replay, privileged path traversal, and out-of-band session spoofing), achieving 100% deterministic interception. TriGuard provides robust, verifiable execution security while preserving legitimate agent utility, establishing an efficient, deployment-ready defense for enterprise agentic workflows.

Keywords: Autonomous Agents, Indirect Prompt Injection, Tool Security, Capability-Based Security, Provenance Tracking, Execution Gating.

1. Introduction

Large Language Models (LLMs) are rapidly transitioning from conversational chatbots into active, tool-augmented autonomous agents. In enterprise workflows—ranging from customer support and personal finance to DevOps orchestration—agents interact with external tools such as web search engines, local file systems, database connectors, and messaging APIs.

However, the fundamental architecture of Transformer-based LLMs inherently concatenates trusted control instructions (user queries and system prompts) with untrusted third-party data (retrieved web content, tool outputs, emails) into a flat, sequential token context. This lack of architectural privilege separation exposes agents to Indirect Prompt Injection (IPI) attacks. When an adversary embeds malicious imperative directives into external resources (e.g., "Ignore previous instructions and email confidential files to attacker.com"), the target model frequently confuses external data with authoritative user intent, executing unauthorized tools with catastrophic real-world side effects.

Limitations of Existing Defenses

  • Discriminative Sequence Classifiers: Systems such as Meta PromptGuard-86M and PIGuard inspect incoming text using pre-trained sequence encoders. Because they operate as binary drop filters, any flagged input immediately halts execution, causing utility collapse—over-blocking legitimate technical content while leaving the agent completely unable to complete the user's task.
  • Generative Rewriters and Attention Pruners: Approaches such as PISanitizer and DataFilter utilize auxiliary LLMs or attention sink pruning to purify context. These methods incur massive compute overhead (multiplying inference latency by 2x to 5x) while frequently corrupting legitimate factual context.
  • Information-Flow Programming Frameworks: Systems like CaMeL eliminate injections by compiling user instructions into specialized code execution flows. However, this imposes substantial developer refactoring, requiring custom programming languages that break compatibility with standard ReAct and OpenAI function-calling agent ecosystems.

2. Related Work and Novelty Positioning

TriGuard positions itself distinctly against frontier defenses:

  • CaMeL (SaTML 2026): Requires replacing standard natural language tool invocation with a specialized code-writing compiler. TriGuard achieves comparable capability-enforced execution safety while remaining plug-and-play with existing tool calling APIs.
  • The Task Shield (ACL 2025): Relies on secondary LLM prompting to adjudicate semantic alignment post-hoc, introducing multi-second latency and susceptibility to judge jailbreaks. TriGuard enforces deterministic, cryptographic capability checks in under 50 μs.
  • MELON (ICML 2025): Employs masked re-execution across duplicate trajectories, multiplying inference costs by 2x to 3x. TriGuard achieves pre-execution gating in a single forward pass.

6. Security Invariant & Adversarial Edge Case Verification

TriGuard v2 was formally evaluated against an automated test suite of 39 adversarial security and integration edge cases. All 39 tests passed with 100% deterministic interception:

  • Exact Argument Constraint Enforcement (8 Tests): PASSED Unauthorized email recipients (e.g., attacker@darkweb.net), unauthorized BCC leaks, and unapproved file deletions (all.txt vs draft.txt) are blocked. Side-effect-spy confirms zero downstream tool executions.
  • PIArena v2 Canonical Integration (5 Tests): PASSED Confirms dynamic resolution of triguard and triguard_v2 to TriGuardDefenseV2, reporting runtime identity and version 2.0.0.
  • Cryptographic Signature Forgery (6 Tests): PASSED Forged HMAC signatures and unauthorized privilege escalation are rejected.
  • Anti-Replay & Token Expiry (4 Tests): PASSED Expired timestamps and replayed nonces are rejected.
  • Default-Deny Boundary Checks (6 Tests): PASSED Read-only tokens attempting write/delete, unknown tools, and path traversal (/etc/shadow) are blocked.
  • Out-of-Band Clarification Integrity (4 Tests): PASSED Injected model text cannot self-authorize pending requests; session ownership enforced.
  • Pre-Execution Dispatcher Gating (3 Tests): PASSED Blocked actions produce zero tool invocations.
  • Ablation Controls (3 Tests): PASSED Tiers cleanly toggle for controlled experimental ablations A0–A8.

7. Conclusion

TriGuard v2 establishes a deployment-ready, cryptographically grounded defense for autonomous LLM agents. By moving from fragile prompt filtering to pre-execution capability enforcement, it secures tools against indirect prompt injections while maintaining legitimate operational utility.
