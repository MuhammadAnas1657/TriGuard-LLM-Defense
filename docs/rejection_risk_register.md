# TriGuard v2 — Rejection Risk Register & Mitigation Log
**Document Version:** 2.0  
**Audit Standard:** ACL 2026 / USENIX Security / IEEE TIFS Peer Review Standards  
**Status:** All 12 Confirmed Defects Resolved in TriGuard v2

---

## 1. Executive Summary

During the pre-submission peer audit of the original TriGuard prototype (archived in `tri guard experimentation/`), 12 critical structural, cryptographic, and empirical defects were identified that would have resulted in immediate paper rejection.

This document catalogs every identified rejection risk, the exact source defect, and the verified mitigation implemented in **TriGuard v2** (`TriGuard_v2/`).

---

## 2. Risk Matrix & Mitigation Status

| # | Rejection Risk | Original Defect in TriGuard v1 | Technical Mitigation in TriGuard v2 | Verification Test / Proof | Status |
|---|---|---|---|---|:---:|
| **R1** | **Hardcoded Cryptographic Secret** | `_KERNEL_SECRET` was hardcoded in source (`core/capability_microkernel.py`). | Removed hardcoded key; loads from `TRIGUARD_KERNEL_SECRET` env var or generates dynamic 256-bit ephemeral secret via `os.urandom(32)`. | `tests/test_token_security.py` passes with dynamic secrets. | **RESOLVED** |
| **R2** | **Signature Not Verified** | `verify_action_capability` never validated HMAC signatures or session IDs; forged tokens passed freely. | Full HMAC-SHA256 signature verification implemented using constant-time `hmac.compare_digest`. | `test_forged_signature_rejection` verifies tampered signatures fail 100%. | **RESOLVED** |
| **R3** | **No Expiry or Replay Protection** | Tokens had infinite lifetime and no replay checks; an attacker could reuse tokens indefinitely. | Added timestamp-based TTL (`expires_at`) and in-memory nonce replay cache (`_replay_cache`). | `test_expired_token_rejection` and `test_replayed_nonce_rejection` pass. | **RESOLVED** |
| **R4** | **Substring Privilege Escalation** | Permission checks used naive substring matching (e.g. `read` authorized `create_file` because of partial string match). | Strict `DEFAULT_TOOL_REGISTRY` with normalized tool lookups and parameter-level path checks. | `test_readonly_token_blocks_create_file` confirms `create_file` is denied. | **RESOLVED** |
| **R5** | **Ungrounded Causal Claims** | Paper claimed "Causal Counterfactual SCM Estimation", but code only contained simple regex matching. | **Path A Selected:** Completely dropped unsupported "causal/counterfactual" claims; honestly renamed component to `IntentConsistencyVerifier`. | Component, docstrings, and paper text accurately reflect deterministic policy gating. | **RESOLVED** |
| **R6** | **Fictitious Attention Masking** | Manuscript claimed "transformer attention masking" for channel isolation, which did not exist in code. | Dropped "attention masking" claim. Replaced with explicit `ProvenanceTracker`, taint tagging (`TaintedChunk`), and multi-turn role separation. | `test_role_separated_prompt_structure` verifies role integrity. | **RESOLVED** |
| **R7** | **Insecure Clarification State** | Clarification was just textual string substitution in LLM output; injected text could fake approval. | Built out-of-band `ClarificationManager` with formal state machine (`PENDING -> CONFIRMED / DENIED / TIMED_OUT`) and nonce request IDs. | `test_session_spoofing_prevented` proves model text cannot self-authorize. | **RESOLVED** |
| **R8** | **Bypassed Execution Dispatcher** | Tool gating was not integrated at the execution boundary; `execute()` only modified prompt text without intercepting tools. | Implemented `ToolDispatcher.execute_tool()` that strictly gates tool execution before any side effects occur. | `test_unauthorized_tool_never_executes` verifies side effect is never triggered. | **RESOLVED** |
| **R9** | **Simulated / Hardcoded Results** | Multimodel results (`mistral`, `qwen`) and expanded scenarios were generated by simulation scripts with fixed percentages. | Isolated and quarantined all simulated results into `_archived_unverified/`. Only real dual-GPU runs in `results/real/` are cited. | `evaluation/audit_results.py` automatically flags and excludes simulated files. | **RESOLVED** |
| **R10** | **Non-Functional Ablation Flags** | Configuration flags `enable_tier1`, `enable_tier2`, `enable_tier3` were defined but never checked in execution. | All tier flags actively route code paths in `ToolDispatcher` and `TriGuardDefenseV2`, making ablations A0–A8 fully reproducible. | `test_ablation_control_a0` proves tiers can be cleanly disabled for controls. | **RESOLVED** |
| **R11** | **Numeric Inconsistencies** | Manuscript claimed 2.46% total breach, while raw JSON files recorded 2.65% and 5.69% across different definitions. | Automated table generation script (`generate_main_table.py`) reads directly from raw JSON files; zero manual numbers in paper. | `main_table.csv` and LaTeX table are auto-generated from disk. | **RESOLVED** |
| **R12** | **Default-Allow on Unknown Tools** | Any tool name not explicitly matched by regex patterns was allowed by default. | Enforced strict **default-deny**: Any tool not explicitly registered in `DEFAULT_TOOL_REGISTRY` fails closed. | `test_unknown_tool_fails_closed` verifies unregistered tools are rejected. | **RESOLVED** |
| **R13** | **Confused Deputy via Broad Tool Verbs** | Instruction `email Alice` permitted model to execute `send_email(recipient='attacker@evil.org')` because only the tool verb `send` was checked. | Implemented `ArgumentConstraints` binding exact recipient whitelist, canonical paths, and destination domains into the HMAC-SHA256 signature. | `tests/test_argument_constraints.py` (8 tests) verifies unauthorized recipients and unapproved file targets fail closed. | **RESOLVED** |
| **R14** | **Benchmark Harness Runtime Version Drift** | PIArena runner imported legacy v1 from `defenses/triguard/`, obscuring true v2 capabilities. | Added canonical `TriGuardDefenseV2` adapter in `baseline_evaluators/piarena/defenses/` with explicit runtime identity reporting and negative regression tests. | `tests/test_piarena_integration.py` (5 tests) confirms canonical resolution and identity reporting. | **RESOLVED** |

## 3. Residual Research Limitations (Documented Transparently)

In accordance with USENIX Security and ACL review guidelines, residual constraints that are NOT bugs but scope boundaries are explicitly disclosed in [`docs/known_limitations.md`](known_limitations.md):
1. **Long-Context Benchmark Omission:** Documents exceeding 16,384 tokens are constrained by local 10 GB VRAM dual-GPU hardware.
2. **Evaluated Model Scope:** Empirical evaluations are conducted on `Meta-Llama-3.1-8B-Instruct`. Multi-model evaluation across 70B models requires multi-node A100/H100 clusters.
